# 진주랭킹 커뮤니티 기능 변경안

작업 브랜치: `changes/community`. 운영 배포 및 Supabase 운영 DB 적용은 보류.

## 작업 범위

1. **계정·권한**: 요청한 로그인 안내, 사이트 전용 닉네임(1~10자 한글·영문·숫자, 대소문자 무시 중복 검사), 기본 30일 변경 제한, 관리자 금칙어 편집과 계정 차단. 카카오에서 가져온 이름·이메일·프로필 사진을 앱의 새 테이블에 저장하거나 화면에 표시하지 않는다.
2. **의견 나누기**: 기존 댓글 디자인과 1인 1댓글·삭제 후 재작성·신고·숨김 유지. 작성자 닉네임과 공감 토글 추가. 공감자는 공개하지 않는다.
3. **자동 썸네일**: 기존 후보 선택 로직 유지. 좌우 사진 아래 이름 칸과 2줄 말줄임 추가.
4. **랭킹 제안·설문**: 기존 공용 에디터와 승인 흐름 유지. 내 제안 상태·대기 취소·반려 메모 추가. 제안 하루 3회와 후보 수·중복 이름·사진 경로를 서버에서도 검사. 설문 작성은 로그인·닉네임 필수.
5. **양자택일**: 랭킹전 탭의 카드, 투표 후에만 서버 집계 공개, 계정당 한 표, 변경 불가. 관리자 질문·A/B·부연설명·공개/보관 편집.
6. **요즘 유튜브 뭐봄**: PC 4열×3행, 모바일 2열×6행. 영상 임베드 없이 썸네일만 표시하고 새 탭으로 연결. 서버가 월요일 한국 시각 09:00 기준 주간 제한을 계산. 12개씩 페이지를 만들고 최신 페이지로 시작. 닉네임 표시, 신고 3회 자동 가림, 운영자 숨김/복구/삭제/계정 차단. 신고 기준은 관리자 설정에서 수정 가능.
7. **댓글 디자인 교체**: 보류. 첨부 이미지는 안내 문구 일부이며 댓글창 전체 디자인 참고 자료가 아니다. 기존 디자인 유지.

## 배포할 때 할 일

- 기존 운영 DB에는 **`supabase/migrations/20261012_community.sql`만** 적용한다. `schema.sql`과 seed를 운영 DB에서 다시 실행하지 않는다. 마이그레이션은 트랜잭션이며 재실행 가능하게 작성했다.
- 새 DB라면 `schema.sql` → 위 마이그레이션 순서로 설치한다.
- 이 SQL을 실행하면 기존 계정도 닉네임을 설정해야 참여 기능을 쓸 수 있다. 운영 DB 적용과 새 프런트 배포를 같은 배포 작업에서 진행한다.
- 변경 브랜치를 main에 합치면 기존 Vercel 자동 배포가 실행된다. 현재는 합치지 않았다.
- 운영 Supabase 연결/새 카카오 계정 실기기 인증은 이번 작업에서 수행하지 않았다. 배포 시 두 실제 계정으로 확인한다.
- 기존 카카오/Supabase Auth가 인증 제공자로부터 보관하는 기본 사용자 메타데이터는 앱의 신규 profiles 테이블과 별개다. 이번 변경에서는 이를 복사하거나 표시하지 않는다. 인증 제공자 자체에 보관되는 정보까지 제거하려면 현재 카카오 동의항목과 Supabase Auth 설정을 따로 확인해야 한다.

## 관리 화면

- **계정·이용 규칙**: 닉네임별 차단/해제, 쉼표로 금칙어 편집, 닉네임 변경 간격, TV 신고 기준.
- **양자택일**: 새 질문 등록 및 수정·보관.
- **유튜브 TV**: 전체 추천을 최신순으로 보고 숨김·복구·삭제·계정 차단.
- 복구한 영상은 운영자가 검토한 것으로 처리해 누적 신고 수에 의한 자동 숨김을 해제한다. 수동 숨김은 계속 가능하다.
- 영상 삭제는 영상 ID를 제거하며 복구할 수 없다. 자리와 주간 사용 기록은 유지한다. 삭제로 다음 추천 자격이 생기지 않는다.
- 썸네일 요청 실패 또는 유튜브의 작은 기본 오류 이미지는 꺼진 TV로 표시한다. 영상을 재생하거나 제목·공개 상태 API를 조회하지 않으므로 정상 썸네일을 계속 제공하는 삭제/제한 영상까지 판별하지는 않는다.

## 개인정보처리방침 추가 문구 초안

진주랭킹은 이용자가 직접 정한 사이트용 닉네임, 내부 회원 식별값, 닉네임 변경 시각과 이용 제한 여부를 저장합니다. 닉네임은 댓글과 유튜브 추천 TV에 표시되며, 내부 회원 식별값과 연결된 계정 정보는 다른 이용자에게 공개하지 않습니다.

닉네임은 작성자 표시, 중복 사용 방지, 변경 주기 관리와 부정 이용 방지를 위해 사용합니다. 댓글 공감, 양자택일 투표, 영상 추천·신고 기록은 중복 참여 방지와 집계·운영을 위해 저장합니다. 영상 추천을 삭제해도 해당 주의 추천 횟수와 TV 자리를 유지하는 데 필요한 기록은 남습니다. 계정 및 관련 정보의 삭제는 개인정보처리방침에 기재된 문의처로 요청할 수 있습니다.

위 초안은 수정 브랜치의 개인정보처리방침 화면에도 추가했다.

## 검증

- `npm run build`: 타입 검사와 Vite 배포 빌드.
- `npm test`: 기존 대결·검증 규칙.
- `npm run test:db`: 기존 DB 규칙 76개.
- `npm run test:community`: 기존 스키마 위에 새 SQL을 두 번 적용한 뒤 다계정 RLS/닉네임/댓글 공감/제안 승인/설문/양자택일/TV/신고/차단/주간 경계를 검증. 실제 PostgreSQL 기반 PGlite에서 실행하며 운영 DB는 변경하지 않는다.
- 브라우저 렌더링 테스트는 로컬 Chromium 실행 파일 다운로드 실패로 수행하지 못했다. 배포 전 모바일·PC 화면과 실제 카카오 인증을 확인해야 한다.
